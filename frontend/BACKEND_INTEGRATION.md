# Контракт підключення frontend до backend

Frontend очікує JSON API на тому самому origin або за `VITE_API_BASE_URL`. Клієнт надсилає `credentials: "include"`; сервер керує сесією через `HttpOnly; Secure; SameSite=Lax` cookie. Сервер має перевіряти `Origin` для запитів, що змінюють стан. Найпростіше розмістити API на тому самому origin. Якщо origin окремий, потрібен CORS із credentials лише для точного origin frontend; для різних site потрібен `SameSite=None; Secure`. Паролі на сервері треба хешувати; frontend не зберігає їх у сховищі браузера.

| Метод і маршрут | Запит | Відповідь |
| --- | --- | --- |
| `GET /api/auth/session` | — | `200 {"user":{"id":1,"display_name":"...","email":"..."}}` або `200 {"user":null}` |
| `POST /api/auth/register` | `{"display_name":"...","email":"...","password":"..."}` | `201 {"user":{...}}` і сесійна cookie; `409` для зайнятої пошти |
| `POST /api/auth/login` | `{"email":"...","password":"..."}` | `200 {"user":{...}}` і сесійна cookie; `401` для невірних даних |
| `POST /api/auth/logout` | — | `204` і видалення cookie |
| `POST /api/assessments/preview` | Такий самий JSON, як для оцінювання | `200` з тим самим форматом результату, **без будь-якого запису** в БД |
| `POST /api/assessments` | Див. `docs/api-contract.md` | `201` зі збереженим результатом, тільки для авторизованого користувача |
| `GET /api/patients/{id}/assessments` | — | `200` зі списком, тільки для авторизованого користувача з правом доступу до пацієнта |

`POST /api/assessments/preview` має не зберігати вхідні дані чи результат також у логах або кеші. Для всіх медичних відповідей встановіть `Cache-Control: no-store`. Перевірка прав, ізоляція даних між акаунтами і остаточна валідація виконуються сервером. Frontend не може забезпечити їх самостійно. Наразі цих маршрутів у backend репозиторію немає; до їх реалізації працює лише приватна демоверсія з тестовими відповідями.
