# Контракт API між Frontend і Backend

Єдине джерело домовленостей між клієнтом і сервером. Якщо змінюється поле
чи маршрут, спершу оновлюють цей файл, потім код з обох боків.

Формат: REST, JSON, кодування UTF-8. Базова адреса — `src/config.js` (клієнт).

## Маршрути

| Метод | Адреса | Призначення | Успіх |
| --- | --- | --- | --- |
| GET | `/api/reference` | Граничні значення для підказок у формі | 200 |
| POST | `/api/assessments` | Нове оцінювання | 201 |
| GET | `/api/patients/{id}/assessments` | Історія оцінювань пацієнта, новіші зверху | 200 |

## POST /api/assessments — запит

| Поле | Тип | Обов'язкове | Примітка |
| --- | --- | --- | --- |
| `patient_id` | ціле ≥ 1 | ні | |
| `sex` | `male` / `female` | так | |
| `age` | ціле 18–120 | так | CKD-EPI 2021 лише для дорослих |
| `creatinine` | число > 0 | так | |
| `creatinine_unit` | `umol_l` / `mg_dl` | ні, `umol_l` | |
| `hemoglobin` | число > 0 | так | |
| `hemoglobin_unit` | `g_l` / `g_dl` | ні, `g_l` | |
| `rbc` | число > 0 | ні | ×10¹²/л |
| `egfr_lab` | число | ні | ШКФ від лабораторії; якщо немає — сервер рахує сам |
| `on_dialysis` | так / ні | ні, `false` | |
| `pregnant` | так / ні | ні, `false` | лише для жінок |

Інших полів сервер не приймає (422).

## POST /api/assessments — відповідь 201

| Поле | Тип | Примітка |
| --- | --- | --- |
| `id`, `patient_id` | ціле або null | |
| `egfr` | число | мл/хв/1,73 м² |
| `egfr_display` | рядок | показувати саме його; `"> 100"`, якщо розрахована ШКФ вища за 100 |
| `egfr_source` | `lab` / `ckd_epi_2021` | |
| `gfr_category` | `G1`, `G2`, `G3a`, `G3b`, `G4`, `G5` | |
| `hemoglobin_g_l` | число | уже переведене в г/л |
| `anemia_grade` | `none` / `mild` / `moderate` / `severe` | підписи — `src/i18n/labels.js` |
| `rbc_status` | `low` / `normal` / `high` або null | лише інформаційно |
| `measures` | список рядків | заходи **для розгляду** лікарем, не призначення |
| `warnings` | список рядків | |
| `guideline_version` | рядок | |
| `created_at` | дата-час або null | |

## Граничні значення (GET /api/reference)

| Показник | Чоловіки | Жінки | Одиниця |
| --- | --- | --- | --- |
| ШКФ (`egfr_lab`) | 0–100 | 0–100 | мл/хв/1,73 м² |
| Креатинін | 40–1000 | 60–1000 | мкмоль/л |
| Гемоглобін | 40–170 | 30–160 | г/л |
| Еритроцити | 1–6 | 1–5 | ×10¹²/л |

Межі включні. Сервер перевіряє їх після переведення одиниць.

## Помилки

| Код | Коли | Що показує клієнт |
| --- | --- | --- |
| 422 | Некоректні дані або вихід за граничні значення | Повідомлення біля відповідного поля |
| 404 | Пацієнта не знайдено | Загальне повідомлення |
| 500 / мережа | Збій сервера або зв'язку | «Не вдалося отримати результат», кнопка знову активна |

Узгоджений формат тіла 422:

```json
{ "detail": [
  { "field": "hemoglobin", "message": "Гемоглобін 170 г/л поза межами 30–160 г/л для жінок" }
] }
```

## Відкриті питання

- [ ] **Backend:** зараз помилки меж повертаються стандартним форматом FastAPI
  (`loc: ["body"]`, усі повідомлення в одному `msg`). Треба додати обробник
  помилок, який віддає формат вище — окремий запис і `field` для кожного поля.
- [ ] **Frontend:** у формі додати поля `egfr_lab` і `pregnant`, яких немає в
  звіті Frontend, але які приймає сервер.
- [ ] **Обидва:** чи віддає FastAPI статичні файли `frontend/` (той самий origin),
  чи клієнт працює окремо і потрібен CORS.
